Section 01

Virtual Network (VNet)

🌐

What Is a VNet?

An isolated, private network in Azure. All Azure resources (VMs, databases, apps) live inside a VNet. It's your own address space in the cloud — like a private datacenter network.

CIDR: 10.0.0.0/16 Region-scoped
⚡

Key Properties

  • Address space defined via CIDR (e.g. 10.0.0.0/16)
  • Scoped to a single Azure region
  • Segmented into subnets
  • Free — no cost for VNet itself
  • Cross-VNet via Peering or VPN
Section 02

Subnets & NSGs

Subnets

Subdivisions of a VNet's address space. Each subnet gets a CIDR range and can host specific resources.

  • Azure reserves 5 IPs per subnet
  • Resources in same VNet communicate freely
  • Dedicated subnets: GatewaySubnet, AzureFirewallSubnet, AzureBastionSubnet

Network Security Groups

Stateful firewall rules attached to subnets or NICs. Filter traffic by source, destination, port, and protocol.

  • Priority: 100–4096 (lower = first)
  • Default: allow VNet ↔ VNet, deny inbound internet
  • Attach to subnet (all resources) or NIC (single resource)

Load Balancing Services

⚖️

Azure Load Balancer

Layer 4 (TCP/UDP). Distributes traffic to VMs within a region. Ultra-fast, millions of flows/sec.

L4 Regional Public / Internal
🛡️

Application Gateway

Layer 7 (HTTP/S). URL-based routing, SSL offload, WAF, cookie affinity. Regional web app LB.

L7 WAF SSL Termination
🌍

Azure Front Door

Global L7. CDN + LB + WAF at Microsoft's edge. Accelerates global apps with anycast.

Global CDN Anycast

Section 04

VNet Peering

🔗

What Is It?

Connects two VNets so resources communicate over Microsoft's backbone — private, low-latency, high-bandwidth. No gateway needed.

  • Regional — same region, free traffic
  • Global — cross-region, egress charges
  • Non-transitive (A↔B, B↔C ≠ A↔C)
  • No overlapping CIDR allowed

Section 05

Azure DNS

📛

Public DNS Zones

Host your domain's DNS records (A, CNAME, MX, TXT) on Azure's global nameserver network. 100% SLA with anycast.

  • Supports alias records for Azure resources
  • Integrates with Traffic Manager
  • RBAC on DNS management
🔒

Private DNS Zones

Name resolution inside VNets — no custom DNS server needed. Auto-registers VM hostnames.

  • Link to one or more VNets
  • Auto-registration of VM names
  • Critical for Private Endpoints (e.g. privatelink.database.windows.net)
Section 06

Hybrid: VPN Gateway

Site-to-Site VPN

Encrypted IPsec tunnel between on-premises and Azure VNet over public internet.

  • Up to 10 Gbps (VpnGw5)
  • Requires GatewaySubnet (/27 minimum)
  • Active-Active for HA

Point-to-Site VPN

Individual client → Azure VNet connection. For remote developers/admins.

Azure ExpressRoute

⚡

Private Dedicated Connection

A private fiber link from your datacenter to Azure — does NOT traverse the public internet. Lower latency, higher throughput, more reliable than VPN.

  • Speeds: 50 Mbps – 100 Gbps
  • Uses BGP for dynamic routing
  • 99.95% SLA (99.99% with redundant circuits)

Section 07

Network Security

🔥

Azure Firewall

Managed L3-L7 firewall. FQDN filtering, threat intelligence, centralized logging. Deploy in hub VNet.

🏰

Azure Bastion

Managed jump host. RDP/SSH to VMs via browser — no public IPs needed on VMs. Zero-attack-surface access.

🔐

Private Link / Endpoints

Access Azure PaaS (SQL, Storage, Key Vault) via private IP inside your VNet. Traffic stays on Microsoft backbone.

🛡️

DDoS Protection

Always-on traffic monitoring. Basic (free, auto-enabled) or Standard (adaptive tuning, cost protection, SLA).

Section 08

NAT Gateway & Network Watcher

🔄

NAT Gateway

Provides outbound internet connectivity for VMs in private subnets using a static public IP. Fully managed SNAT.

  • Up to 16 public IPs (64K SNAT ports each)
  • Eliminates SNAT exhaustion
  • Attach to subnet — all VMs auto-use it
  • Outbound only — no inbound initiation
🔍

Network Watcher

Diagnostic and monitoring toolkit for Azure networks.

  • IP Flow Verify — is traffic allowed?
  • Next Hop — where does packet go?
  • NSG Flow Logs — who's talking to whom
  • Connection Troubleshoot — end-to-end test
  • Packet Capture — capture on VM NIC
  • Topology — visual network map

Section 09 — Security Pattern

Zero Trust Network Model

🔒

Verify Explicitly

  • Managed Identity for all services
  • Conditional Access policies
  • MFA for all admin access
🎯

Least Privilege

  • NSGs: deny-all default, allow specific
  • Private Endpoints for all PaaS
  • No public IPs on VMs
💥

Assume Breach

  • Micro-segmentation with NSGs
  • Azure Firewall for east-west traffic
  • NSG flow logs + Microsoft Sentinel

Summary

Key Takeaways

  • VNet is your foundation — design address spaces and subnets before deploying anything
  • NSGs are your first line of defense — apply at subnet level with deny-all baseline
  • Use Private Endpoints for PaaS — eliminate public exposure for SQL, Storage, Key Vault
  • Pick the right LB — L4 for VMs, App Gateway for web, Front Door for global
  • Hub-Spoke for enterprise — centralize firewall, gateway, monitoring in the hub
  • ExpressRoute for mission-critical — VPN for dev/test, ExpressRoute for production hybrid
  • Network Watcher is your debugger — use IP Flow Verify and Connection Troubleshoot first
